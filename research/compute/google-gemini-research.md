## Concrete public-benefit proposal

The candidate study asks: **When relevant evidence is absent or contradictory, can an evaluation protocol distinguish justified abstention from fabricated certainty in AI technical recommendations?** This connects to the existing [research comparison](https://github.com/Pick-Your-AI/pick-your-ai-research/issues/41) and [Leaderboard research needs](https://github.com/Pick-Your-AI/pick-your-ai-leaderboard/issues/25); those owners retain their implementation and acceptance responsibilities.

Proposed scale: 120 original technical cases × two evidence conditions × three repetitions = **720 requests per selected model**, before any separately approved pilot/retry allowance. This is an explicit proposed scope, not usage evidence. A responsible investigator would preregister scoring, independently validate ground truth, retain all failures, publish corpus/scoring code and report uncertainty alongside results. Use original non-sensitive synthetic facts and ordinary generation without Search/Maps grounding. Keep a finite offline research job; public publication of a report is not a live API application for minors.

Existing project tests and fixtures provide a no-credit way to develop the evaluation machinery. They do not measure a model. No paid request, participant study, public deployment or empirical result follows from this memo. Any academic affiliation, authorship or institutional approval must be real before representation in an application.

## API, data and publication conditions

G3 requires adult access and restricts clients directed at or likely used by minors, regional availability, competing-model development, reverse engineering and safeguard bypass. EEA/Swiss/UK client availability has a paid-service condition. Generated content is not claimed by Google, but rights and factual correctness remain the user's responsibility. Grounding has additional restrictions; it is excluded from this proposal.

For ordinary unpaid API use, G3 allows product improvement and human review of content; sensitive information should not be submitted. Paid API treatment depends on an **active billing-linked Cloud project**, not simply receiving a grant. Paid content is not used for product improvement, but safety/legal logging remains. Regional exceptions apply. The actual grant's billing/data classification is therefore **Unknown**, not presumed confidential or zero-retention.

G4 separately requires authority to bind an entity, necessary content rights and API attribution. It restricts unsupported partnership/endorsement claims and permits certain provider promotional depictions. It also addresses user-data portability and discontinuation. These are not permission to publish third-party protected material or a promise of perpetual access. Maintain an independent local archive of permitted original research inputs, methods and outputs, with an exit plan that does not depend on continued API service.

G8 provides general retention/deletion controls and permits retention for different purposes; institutional administrators may control account access and data. No program-specific proposal deletion period or account-specific control has been verified. The nonconfidential application and the API data regime are different scopes.

Grant-specific acknowledgment, embargo, sponsor review, data-release, reporting and renewal obligations remain Unknown. An internal condition of pursuit is that funding cannot dictate methodology, rankings or suppression of unfavorable findings. Disclose actual support accurately if it is awarded; this memo establishes no sponsorship.
