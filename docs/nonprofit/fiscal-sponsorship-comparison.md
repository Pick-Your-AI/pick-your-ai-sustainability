### Fee and agreement qualifications

- **SFC:** the application FAQ's processed-revenue description and template's gross-revenue provision need a written scope decision in the negotiated agreement. The template is linked as an example, not a form to execute immediately. Its example committee size is negotiable; it is not an extra universal admission rule. [S1, S3]
- **OSC:** the public intake links an agreement whose Exhibit A applies 10% to deposits regardless of source, while current operational guidance exempts internal OSC transfers. Neither statement is silently discarded. Ask for the applicable version and written reconciliation before adopting a fee base. Protocol-change notice periods in different provisions also need clarification. [O3, O4, O6]
- **GitHub Sponsors:** current GitHub documentation lists SPI and OSC as fiscal-host payout options. SFC is not listed there; other possible SFC arrangements remain Unknown. A verified host relationship and the relevant account setup are required. [G1]
- **Upstream fees:** GitHub distinguishes personal-account sponsorships without its fee from organization sponsorships with charges up to 6%, with an invoicing adjustment. OSC's integration guide's general no-GitHub-fee wording cannot establish that every sponsorship is free. Host fees and other processors remain separate. [G2, O11]

## Value, effort and unsent inquiry checklist

Use the accepted [needs assessment](../funding/needs-assessment.md) to identify which contracting, donation, expense, asset or administration tasks a host would actually cover. Required effort is the work to assemble rights/authority/community evidence, compare written terms, establish roles and maintain financial reporting. Hours and people commitments are **Unknown** until a scoped plan is accepted. A lower headline percentage does not establish lower total cost or better fit.

Estimate each candidate as `verified qualifying fee base × applicable host rate + verified processor/FX charges + quoted exceptional services + scoped migration/administration cost`. Reconcile gross receipts, upstream charges and host-deposit timing so the same processor cost is not counted twice. Compare equivalent services and horizons. Keep received cash, restrictions, contingent awards, credit face value and evidenced avoided cost separate. Hosting itself awards no money; its potential avoided administration cost requires a real alternative quote or documented effort baseline. Complete net value and award probability remain Unknown; no numeric score is manufactured.

The following is an **unsent common inquiry preparation checklist**, not an instruction to contact anyone:

1. Record the actual applicant, authorized decision/signature process, project history, administrators/liaison, succession method and complete license/IP inventory. Do not substitute GitHub authorship for legal authority.
2. Map the public-benefit deliverables and accepted needs to requested services; state the current development stage and unresolved maturity evidence accurately.
3. Ask which admission route and evidence apply, the actual process and expected workload, and whether an existing entity or host changes the proposed arrangement.
4. Obtain the applicable agreement/version, qualifying fee base, processor and exceptional charges, taxes, reporting cadence, expense approval process and contract authority. Ask SFC and OSC to resolve the specific fee-base differences above in writing.
5. Ask about restricted funds, donor receipts, publication/branding requirements, privacy roles, IP/domain/equipment custody, indemnity and dispute terms, change notices and permitted successor/exit costs.
6. Confirm the precise GitHub Sponsors route and any separate provider eligibility. Prepare a comparison for an authorized project decision; do not present a research recommendation as acceptance or spending authority.
