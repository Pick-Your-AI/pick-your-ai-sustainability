## Material workflow findings

**A contributor can keep incomplete discovery truthful.** The Markdown note can exist before a program is eligible for the live register. It records the exact provider/program/round and aliases, the scope and date of a search actually performed, possible canonical matches and unresolved identities. Repeat rounds or a rename extend the existing opportunity unless a distinct research outcome is justified. Closed, invitation-only, unknown and ineligible findings retain their history.

**The note and JSON have distinct responsibilities.** The mapping names the actual structured fields while retaining per-claim source scope, contradictory terms, missing facts and reasoning in the linked note. Null amounts, dates and people remain unknown; an empty list establishes no absence of obligations. The fill-in JSON is deliberately incomplete. The synthetic fixture's placeholder program URI, E00-00 owning key and P2 input satisfy test shapes only and remain outside the live opportunity, pipeline and freshness registers.

**All three applicant routes remain separate.** Actual community/entity facts, a verified fiscal-sponsor relationship and independent recognition each require the relevant program's conditions. A conditional future route cannot authorize today's application. The recorded benefit, cash, advertised credits, likely usable value and realized avoided cost are different quantities. The rubric requires evidence for each rating; missing factors retain a null total and foundational work can have a justified P1 priority without a grant score.

**Research and action have separate gates.** The outreach file is an unsent draft. Recipient, sender capacity, exact representation, requested commitments and exact-text permission must be established for an actual send. The linked approval form also requires the actual applicant, reviewed version, maximum commitment, authority, validity conditions and execution receipt. An accepted template, schema check, role title or prior provider approval supplies none of these facts. These controls are received as explicit boundaries for this intake, not as adoption of every unfinished #68/#69 procedure.

**The validator is a structural check.** It checks unique JSON keys, supported numeric representations, the schema's required fields and formats, template placeholders, register identity/count/projection consistency, freshness URL membership and local Markdown targets. It uses an explicit offline schema registry. The schema is intentionally not a complete type/enum or evidence validator for every workflow field; a syntactically admitted record still needs the human completeness, evidence, scoring, rights and receiving review described by the note. Tests do not establish a current form, recipient, legal status, score justification, complete restriction assessment or permission to act.

The concrete public-benefit use of this foundational outcome is to let contributors to this repository create one traceable support investigation and hand off evidenced needs to the existing technical repository, without duplicating provider identities or substituting an advertised benefit for usable support. This is an implemented documentation workflow and a demonstrated synthetic mapping. It is not a measured reduction in contributor effort or a provider award.
